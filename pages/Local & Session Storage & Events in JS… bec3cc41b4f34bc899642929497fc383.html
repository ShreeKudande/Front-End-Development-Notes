Local & Session Storage & Events in JS…

Q. Explain me Local Storage in simple words with examples.

Certainly! Local Storage is a feature in web browsers that allows you to store data locally on a user's computer. It provides a way to persistently store key-value pairs within the user's browser.

Think of Local Storage as a small storage box that you have in your room. You can put things in the box and they will stay there even if you leave the room and come back later. Similarly, in web development, Local Storage allows you to store data that will persist even if the user closes the browser or navigates away from the website. The data will remain accessible when they revisit the same website.

Here's an example to illustrate how Local Storage works:

// Storing data in Local Storage
localStorage.setItem("username", "John Doe");
localStorage.setItem("age", "25");

// Retrieving data from Local Storage
var username = localStorage.getItem("username");
var age = localStorage.getItem("age");

console.log(username); // Output: "John Doe"
console.log(age); // Output: "25"

In this example, we use the localStorage object to store two key-value pairs: "username" with the value "John Doe" and "age" with the value "25". The setItem() method is used to store the data.

Later, we retrieve the data from Local Storage using the getItem() method by providing the key. The retrieved values are then assigned to the username and age variables, and we log them to the console.

Local Storage provides a simple way to store and retrieve data, making it useful for various scenarios like remembering user preferences, caching data, or maintaining a user's session state.

It's important to note that Local Storage is limited to storing data as strings. If you need to store complex data types like objects or arrays, you can convert them to JSON strings using JSON.stringify() before storing and parse them back to their original form using JSON.parse() when retrieving.

Also, keep in mind that Local Storage has a size limit (usually around 5MB) and the stored data is accessible only within the same domain and protocol from which it was stored.

I hope this explanation helps you understand Local Storage in simple terms!

Q. Give me a example of using JSON.stringify() and JSON.parse() in JS.

Certainly! Here's an example that demonstrates the usage of JSON.stringify() and JSON.parse() to store and retrieve complex data types like objects using Local Storage:

// Storing an object in Local Storage
var user = {
  name: "John Doe",
  age: 25,
  email: "johndoe@example.com"
};

localStorage.setItem("user", JSON.stringify(user));

// Retrieving and parsing the object from Local Storage
var storedUser = localStorage.getItem("user");
var parsedUser = JSON.parse(storedUser);

console.log(parsedUser.name); // Output: "John Doe"
console.log(parsedUser.age); // Output: 25
console.log(parsedUser.email); // Output: "johndoe@example.com"

In this example, we have an object user containing properties like name, age, and email. We convert this object into a JSON string using JSON.stringify() before storing it in Local Storage using localStorage.setItem().

Later, when we retrieve the string from Local Storage using localStorage.getItem(), we parse it back into its original form as an object using JSON.parse(). The resulting parsedUser object can be accessed and used just like any other JavaScript object.

By using JSON.stringify() and JSON.parse(), we can easily store complex data types in Local Storage as strings and retrieve them in their original format.

Remember that Local Storage is limited to storing strings, so it's necessary to convert complex data types into strings before storing them. JSON (JavaScript Object Notation) provides a convenient way to serialize objects into strings and deserialize them back into objects.

I hope this example clarifies the usage of JSON.stringify() and JSON.parse() for storing and retrieving complex data types in Local Storage!

Q. Explain me Session storage in js, in simple words with examples.

Certainly! Session Storage is similar to Local Storage, but with one key difference: the data stored in Session Storage is only accessible within the same browser tab or window session. Once the session ends (when the user closes the tab or window), the data is cleared and no longer accessible.

Think of Session Storage as a temporary whiteboard that you have in a room. You can write notes or draw pictures on the whiteboard, and they will stay there as long as you are in the room. However, once you leave the room, the whiteboard is wiped clean, and the information is no longer available.

Here's an example to illustrate how Session Storage works:

// Storing data in Session Storage
sessionStorage.setItem("username", "John Doe");
sessionStorage.setItem("age", "25");

// Retrieving data from Session Storage
var username = sessionStorage.getItem("username");
var age = sessionStorage.getItem("age");

console.log(username); // Output: "John Doe"
console.log(age); // Output: "25"

In this example, we use the sessionStorage object to store two key-value pairs: "username" with the value "John Doe" and "age" with the value "25". The setItem() method is used to store the data.

Later, we retrieve the data from Session Storage using the getItem() method by providing the key. The retrieved values are then assigned to the username and age variables, and we log them to the console.

Session Storage is useful when you need to store temporary data during a user's browsing session, such as maintaining state between different pages within the same tab. It's worth noting that Session Storage is limited to the specific browser tab or window where it was set, and the data is cleared when the tab or window is closed.

Just like Local Storage, Session Storage also stores data as strings. If you need to store complex data types like objects or arrays, you can use JSON.stringify() to convert them into strings before storing and JSON.parse() to parse them back into their original form when retrieving.

I hope this explanation helps you understand Session Storage in simple terms!

Q. Explain me Storage Event in js, in simple words with examples.

Certainly! The Storage Event in JavaScript is an event that gets triggered when changes are made to the Local Storage or Session Storage within the same browser tab or window. It allows you to listen for changes in storage and perform actions in response to those changes.

Imagine you have two tabs open in your browser, and you update a value in Local Storage on one tab. The Storage Event allows the other tab to be notified of the change and respond accordingly.

Here's an example to illustrate how the Storage Event works:

// Add an event listener for the Storage Event
window.addEventListener("storage", function(event) {
  if (event.key === "username") {
    console.log("Username has changed!");
    console.log("New value: " + event.newValue);
    console.log("Old value: " + event.oldValue);
  }
});

// Update the value in Local Storage
localStorage.setItem("username", "John Doe");

In this example, we add an event listener to the window object, listening for the "storage" event. When a change occurs in the storage (e.g., Local Storage), the event is triggered.

Inside the event listener function, we check if the key that changed is "username". If it is, we log a message indicating that the username has changed, along with the new and old values.

After adding the event listener, we update the value of "username" in Local Storage using localStorage.setItem(). This change triggers the Storage Event, and the event listener responds by logging the appropriate messages.

The Storage Event is useful when you want to synchronize data between multiple tabs or windows in real-time. It allows different parts of your application to stay in sync and react to changes made in one tab from another tab.

It's important to note that the Storage Event is only triggered when changes are made within the same origin (same domain, protocol, and port). Changes made by different origins (e.g., different websites) will not trigger the Storage Event due to security restrictions.

I hope this explanation helps you understand the Storage Event in simple terms!
